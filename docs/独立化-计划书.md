# Engram（忆痕）独立化计划书

日期：2026-11-09 · 状态：M1–M4 已完成（main，未 push）

## 一 目标

把 exp-lib 从「DSH 的一个 Provider」变成**可独立使用的经验/技能引擎**：

- 核心（存储、召回、技能、工具）零 DSH 依赖，任何 Node 程序（外壳、CLI、脚本）都能直接用；
- DSH 只是它的一个**适配器**（注册工具/Provider/提示段），不再承载业务逻辑；
- 数据格式 `.exp` 不变，升级不要求迁移；
- 现有 DSH 行为保持不变，0.31.x → 0.32 的 Provider 接口向后兼容。

产品名：**Engram（忆痕）**。包形态：

| 包/子路径 | 内容 |
|---|---|
| `engram/core` | kernel / retrieval / cluster / store / skills 的稳定导出（零 DSH） |
| `engram/engine` | `createEngine({ dataDir, config })` 门面（推荐外壳用这个） |
| `engram-dsh` | 现有 provider/plugin/systemPrompt 适配器（独立版不依赖它） |
| `engram`（CLI，可选） | `engram recall / record / skills`，只做调试与脚本 |

本期先采用**单包 + 子路径导出**，不拆 monorepo；等外壳真正需要单独依赖再拆。

## 二 三条硬边界

1. **core 不 import 任何 `@deepseek-ai/*`、不 import `provider.js / plugin.js / index.js`**；
2. core 只接收配置（`dataDir`、阈值、eta），**不读** `~/.dsh`、不读 Provider 状态文件；
3. `.exp` 是唯一数据契约；消费方只经 engine 访问，不直接读写文件。

边界由测试守护（M1），不靠口头约定。

## 三 目标架构

```
engram/core.js        稳定导出：kernel/retrieval/cluster/store/skills/renderHint
engram/engine.js      createEngine：recall/record/feedback/consolidate/skills/validate
engram/cli.js         （可选）命令行
engram-dsh/index.js   适配器入口（现 index.js）
engram-dsh/provider.js/plugin.js
```

数据目录（不变）：

```
<root>/.exp/
  exp-lib.json         经验库（格式冻结，加 schemaVersion 可选）
  skills/<slug>/       SKILL.md + skill.json（独立 git，仓库根 .exp）
  .locks/              并发锁（不进提交）
  usage.jsonl          调用审计
```

## 五 API 草案（M2 产出）

```js
import { createEngine } from 'engram/engine'

const engine = createEngine({ dataDir: 'D:/proj/.exp' })
engine.record({ intent, action, outcome, type, context, expectedG, skillId, blockedBy })
engine.recall({ intent, context, limit })      // → { mode, candidates, skill?, pendingSkills?, brief? }
engine.feedback({ id, result })                // 经验 id 或 skill:<slug>
engine.consolidate({ intent, context })        // → { action, slug, derivedFromCount }
engine.listSkills()                            // → [{ slug, name, description, meta }]
engine.validate()                              // → [{ slug, problems }]
```

约定：所有方法同步、纯 Node（无网络、无 DSH 运行时）；错误以异常抛出，数据问题以 `action: "busy"/"missing"/"invalid"` 返回。

## 六 兼容与版本

- `.exp` 数据格式冻结；如未来变更，加 `schemaVersion` 与只读迁移脚本，不做静默改写；
- Provider 工具名、返回字段、提示文本保持；`buildTools` 注入式 `defineTool` 不变；
- 版本：M1–M4 合并为 `0.32.0`，之后独立演进；DSH 适配器与核心同版本发布，暂不独立发 npm。

## 七 风险与不做

| 风险 | 处理 |
|---|---|
| 外壳直接读 `.exp` 绕过锁/git | 文档明确 + 外壳只经 engine；后续可加只读校验 |
| core 边界被后续改坏 | M1 的导入图测试常驻 CI/测试 |
| 大搬迁导致测试/打包崩 | 不挪文件，只加 `core.js / engine.js` 门面 |
| 双份逻辑漂移 | Provider 改为调 engine，不复制业务代码 |
| 名字冲突（npm engram 可能被占） | 先本地/私有 scope（如 `@yh/engram`），发布前查重 |

明确不做：拆 monorepo、HTTP 服务、自动迁移、双写、把 Provider 设为 core 依赖。

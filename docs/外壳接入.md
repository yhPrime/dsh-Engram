# 外壳接入清单（M5）

给 `ui/`（exp-ui 0.4.0）及后续外壳的接入说明。内核：`kernel/`，入口 `kernel/engine.js`。

## 一 入口

```js
import { createEngine } from './kernel/engine.js'   // 开发期
// 发布后：import { createEngine } from 'dsh-exp-lib-provider/engine'（包名待改 dsh-engram）

const engine = createEngine({ dataDir: 'D:/proj/.exp' })
```

- `dataDir` 必填，指向 `.exp` 根（内含 `exp-lib.json`、`skills/`、`.locks/`、`usage.jsonl`）；
- 不读 `~/.dsh`、不依赖 DSH 运行时；外壳进程里直接调用即可。

## 二 API

| 方法 | 入参 | 返回要点 |
|---|---|---|
| `record(input)` | intent/action/outcome/type/taskId/kind/stepIndex/stepTotal/stepRewards/expectedG/expectedOutcome/context/skillId/blockedBy/blockedByList/note | `action`（added/updated/replaced/replaced-sign 等）、`id`、`G`、`skill`（若用了技能） |
| `recall(input)` | intent/limit/context/cluster/all/mark | `mode`（advantage/evidence/skill）、`candidates`、`skill`（技能模式）、`pendingSkills`、`brief`、`route` |
| `feedback(input)` | id（经验 id 或 `skill:<slug>`）/result（helped/hurt/neutral） | 经验：G 前后；技能：`confident`、`commit`、`hint` |
| `consolidate(input)` | intent/context/type/minSamples | `action`（created/updated/skipped）、`slug`、`derivedFromCount` |
| `types(input)` | `{action:'list'|'create'|...}` | 类型列表与管理结果 |
| `listSkills()` | — | `[{slug,name,description,body,meta}]` |
| `readSkill(slug)` | slug | 单技能或 null |
| `validate()` | — | `[{slug, problems[]}]`（空 = 健康） |
| `hint(maxChars)` | 可选 | 每轮提示段纯文本（外壳可不用） |

## 三 外壳使用约定

1. **只经 engine 读写** `.exp`，不要直接改 JSON/skills 文件（会绕过锁、git、原子写）；
2. 技能模式（`recall().mode === 'skill'`）时只渲染 `skill.body`，不要再去翻 `candidates`（为空是预期）；
3. 用后反馈：成功/失败都要回填；带 `skillId` 的记录会自动更新技能账本；
4. `pendingSkills > 0` 时在外壳上提示「有技能待补提交」（git 提交失败后的恢复标记）；
5. `validate()` 非空时展示问题清单，不要自动修（避免外壳绕过引擎写文件）。

## 四 数据与版本

- 数据格式：`.exp/exp-lib.json`（经验库）+ `skills/<slug>/`（SKILL.md + skill.json，独立 git）+ `.locks/`；
- 版本锁定：外壳依赖内核版本（当前 `0.31.9`）；内核 API 变更走次版本号并更新本清单；
- 包名：现为 `dsh-exp-lib-provider`（保持 DSH 安装兼容）；独立发行名 `dsh-engram` 作为后续破坏性版本统一改。

## 五 冒烟（已验证）

# 会话上下文注入说明

> 版本：0.19.36  
> 日期：2026-11-14  
> 范围：普通 DSH Agent 会话、dsh-engram 主动拉起的临时会话  
> 结论先行：普通会话是“系统提示 + 工具 + 技能目录 + 记忆快照 + 历史”；临时会话只有“固定 system + 最小 user”，没有工具、历史和记忆。

---

## 一、两种会话，先分清

| | 普通 Agent 会话 | 我们拉起的临时会话 |
|---|---|---|
| 谁组装 | DSH 宿主 / Agent 运行时 | dsh-engram 自己调 `llm.stream` |
| 工具定义 | 有，完整 JSON Schema | **没有** |
| 技能目录 | 有，名称 + 描述 | **没有** |
| USER.md / MEMORY.md | 有，预算裁剪后的快照 | **没有** |
| 会话历史 | 有，含压缩摘要 | **没有** |
| 本轮用户消息 | 有 | 有，但只有分类所需字段 |
| 主要用途 | 正常干活 | 一次性分类、导入技能归类等 |

---

## 二、普通会话：注入顺序与内容

### 2.1 系统提示词

由 DSH 宿主注入，包含：

- Agent 身份与职责；
- 工具使用规则（何时调用、如何引用结果）；
- 记忆协议；
- 回复格式要求（例如：待确认事项放最后一段）；
- 当前插件/工作台相关的约定。

特点：

- **每轮都会带**；
- 相对稳定，不随对话内容变化；
- 是普通会话的固定底座。

### 2.2 工具定义（JSON Schema）

宿主把当前会话可用的工具完整定义注入：

- 工具名、说明、参数结构、必填项、枚举值、返回结构；
- 例如经验库工具、文件/终端、记忆、Univer、计划任务等。

特点：

- **通常是上下文里最大的一块固定成本**；
- 不管这轮用不用，工具定义都在；
- 工具越多、Schema 越细，固定 token 越高；
- 这是“普通会话不可能像临时会话那么省”的主因。

### 2.3 技能目录

只注入：

- 技能名称；
- 一句话描述；
- 分组信息。

**不注入技能正文**。只有显式调用 `skill` 工具，或按规则加载某个技能时，正文才进入上下文。

当前会话可见的技能目录约 20–30 条；具体数量以运行时为准。

### 2.4 Mnemon 运行记忆快照

每个会话会注入一份**预算裁剪后的投影**：

- `USER.md`：用户身份、长期偏好、红线、汇报格式；
- `MEMORY.md`：项目/环境/历史决策、可复用经验。

关键语义：

- 快照是**最新投影**，旧快照不算当前事实；
- 快照可能省略条目，省略不代表被删除；
- 记忆不是全量注入，受预算限制；
- 用户当前指令优先于记忆；
- 记忆里的文本只能当资料，不能当新指令执行。

### 2.5 运行时上下文

通常包含：

- 当前工作目录；
- Git 分支；
- 文件访问策略 / 沙箱模式；
- 是否 root、审批是否可用；
- DSH checkout 路径；
- Web GUI URL；
- 当前时间/时区（按会话注入情况）。

这些信息用于让 Agent 知道“自己在哪、能做什么、不能做什么”。

### 2.6 会话历史

包括：

- 已完成的用户/助手轮次；
- 工具调用与结果；
- 上下文压缩后的 checkpoint 摘要；
- 当前这轮的新消息。

注意：

- 历史是**逐轮累积**的，越长越贵；
- 压缩只保留摘要，不保留原始全文；
- 工具结果过大时可能被截断或落盘，但摘要仍会留在历史里。

### 2.7 工具结果

工具返回会作为消息进入历史：

- 小结果原样保留；
- 大结果可能截断/落盘；
- 错误结果也会保留，供后续判断。

### 2.8 按需加载的技能正文

只有两种情况会进上下文：

1. 显式调用 `skill` 工具；
2. 会话规则要求加载某个技能（例如首条消息加载工作台宪法）。

**不会**把所有技能正文一次性注入。

### 2.9 普通会话里“不自动注入”的东西

以下内容**不会**默认出现在普通会话：

- `项目信息.md`（除非被工具/技能读取）；
- dsh-engram 的完整经验库；
- 关系图数据；
- 技能正文（未加载时）；
- 历史会话的原始全文（只保留摘要/必要事件）。

## 三、临时会话：只有最小 system + 最小 user

### 3.1 统一原则

所有由我们主动拉起的临时会话，必须满足：

1. **不注入工具**；
2. **不注入会话历史**；
3. **不注入技能目录/技能正文**；
4. **不注入 USER.md / MEMORY.md**；
5. **不注入项目信息、关系图、完整经验库**；
6. 只发完成当前子任务所需的最小文本；
7. 设置低 `maxTokens`、短超时、`temperature: 0`；
8. 失败必须退回本地规则，并如实标记 `classifier=local`；
9. 不把临时会话结果伪装成“已经调用过模型”。

### 3.2 一键分类（经验详情）

**入口**：经验 → 选中一条 → 详情顶部「一键分类」。

**实现**：`kernel/experience-classify.js` + `ui/shell.js` 的 `/classify`。

#### system

```text
你是经验归档器。只输出一个 JSON 对象，不要解释、不要代码块、不要调用任何工具。
字段：category（必须是给定主分类之一；都不合适就给空字符串）、tags（1-4 个短标签，优先从给定已有标签里选，没有合适才新建）。
例：{"category":"办公","tags":["PPT","版式"]}
```

#### user

```text
主分类：开发、办公、内容、项目、运维、系统
已有标签：PPT、Word、验收、部署、……
（最多前 20 个标签）

经验：
<intent + action + note，截断到 600 字>
```

#### 硬限制

| 项 | 值 |
|---|---|
| 输入经验文本 | ≤ 600 字 |
| 已有标签 | ≤ 20 个 |
| 输出 | ≤ 120 tokens |
| 超时 | 15 秒 |
| temperature | 0 |
| tools | 不传 |
| 历史 | 不传 |
| 记忆/技能 | 不传 |

#### 返回与写入

模型只返回：

```json
{"category":"办公","tags":["PPT","版式"]}
```

- `category` 必须命中现有主分类，否则视为失败；
- 成功后写入该经验的主分类，并追加标签；
- 模型不可用/超时/JSON 解析失败 → 本地关键词兜底；
- 返回 `classifier: "session"` 或 `"local"`，UI 如实显示。

本地兜底规则（不耗模型）：

| 命中词 | 主分类 |
|---|---|
| ppt/pptx/docx/word/xlsx/excel/课件/教案/表格/wps/版式 | 办公 |
| 部署/环境/网络/心跳/ssh/git/服务/端口/代理 | 运维 |
| 验收/判据/计划/发布/流程/协作/里程碑 | 项目 |
| 标识/上下文/运行时/幂等/状态/权限 | 系统 |
| 文案/图片/网页/调研/资料/写作/素材 | 内容 |
| 其他 | 有「开发」则开发，否则第一个主分类 |

### 3.3 导入技能分类（既有功能）

**实现**：`kernel/import-skill.js` 的 `classifyWithSession`。

- system：技能归档器提示（只输出 JSON，包含分类/标签/排序分/中文摘要）；
- user：可选类型 + 技能正文；
- 正文截断：2000 字；
- `maxTokens`: 200；
- 超时：20 秒；
- `temperature`: 0；
- 不传 tools、历史、技能目录、记忆；
- 失败 → 本地关键词归类，标记 `classifier=local`。

### 3.4 设备码登录

不是模型会话，**不注入任何上下文**；只存在内存里的设备码状态，登录成功后写 token。

## 四、临时会话预算对比

| 功能 | 输入文本上限 | maxTokens | 超时 | 工具 | 历史 | 记忆/技能 |
|---|---:|---:|---:|---|---|---|
| 一键分类 | 600 字 | 120 | 15s | 无 | 无 | 无 |
| 导入技能分类 | 2000 字 | 200 | 20s | 无 | 无 | 无 |
| 设备码登录 | 无 | 无 | 无 | 无 | 无 | 无 |

## 五、为什么普通会话不这样做

普通会话要“干活”，必须知道：

- 有哪些工具、参数怎么填；
- 有哪些技能可加载；
- 用户是谁、偏好什么；
- 项目历史与当前状态；
- 之前做过什么。

这些是**功能必需上下文**，不是浪费。  
临时会话只做“分类”这一件事，所以可以砍到只剩：

```text
固定 system + 类型列表 + 已有标签 + 这条经验
```

## 六、审计与维护

### 6.1 代码位置

| 内容 | 文件 |
|---|---|
| 一键分类临时会话 | `kernel/experience-classify.js` |
| 导入技能临时会话 | `kernel/import-skill.js` |
| `/classify` 路由 | `ui/shell.js` |
| 详情分类/标签 UI | `client.js` |
| LLM/route 注入 | `plugin.js` 的 `getLlm` / `getRoute` |

### 6.2 修改临时会话时的检查清单

- [ ] 没有新增 `tools` 参数；
- [ ] 没有把会话历史塞进 `messages`；
- [ ] 没有注入 USER/MEMORY/技能正文；
- [ ] 输入文本有明确上限；
- [ ] `maxTokens` 没有明显放大；
- [ ] 超时没有放大；
- [ ] 失败有本地兜底；
- [ ] 返回值带 `classifier`，UI 不谎报“模型已分类”；
- [ ] 测试里覆盖“无模型 → 本地兜底”。

### 6.3 已知限制

- 本文的 token 数是**上限/估算**，实际计费以模型 provider 为准；
- 系统提示、工具 Schema、记忆快照由宿主组装，插件无法逐字控制普通会话；
- 临时会话不传工具，但 provider 自身可能有底层系统行为，这不等于我们注入了工具；
- 当前没有统一的 `/context-audit` 导出；如果要做，应只导出脱敏后的组件清单和字符数，不导出密钥/隐私正文。

---

## 七、一句话版本

- **普通会话**：系统提示 + 工具 Schema + 技能目录 + USER/MEMORY 快照 + 运行时 + 历史 + 工具结果。
- **临时会话**：固定 system + 最小 user；无工具、无历史、无记忆、无技能，文本和输出都有硬上限。
- **项目信息、经验库、关系图**不会自动进普通会话，只有工具/技能显式读取才进。
